# Pengembangan lewat ohmypi

Jalankan `omp` dari root project. Mulai dengan meminta pembacaan AGENTS.md, lalu jelaskan perubahan dan hasil yang diinginkan.

Setiap pekerjaan memakai TODO yang diperbarui sepanjang proses; subagent hanya untuk bagian yang benar-benar memerlukannya. Setiap perubahan file project diikuti `make build`, pemeriksaan relevan, dan pembaruan Markdown terkait plus `make obsidian`. Setelah hasil terverifikasi, agent otomatis commit file pekerjaan dan push branch aktif ke remote terkonfigurasi, tanpa force-push atau menyertakan perubahan pengguna yang tidak terkait. Deployment tetap memakai `make apply` saat CCode sudah ditutup normal; autopush tidak berarti memaksa app/task berhenti atau menjalankan `make install`.

## Branding dan ikon

Mark CCode berasal dari `ccode-logo.svg`. Dua modul terpisah: `src/local_only/rebrand.py` berjalan paling awal di `scripts/build.py` dan menulis ulang seluruh token produk upstream (env, IPC, skema URL, layout, id plugin, judul proses, identifier) dalam satu pass — `assert_clean()` menggagalkan build bila ada sisa, dan ejaan lama hidup di `rebrand.PREVIOUS_*` untuk kode migrasi; `src/local_only/branding.py` berjalan paling akhir di build dan hanya mengganti mark. Setelah mengubah artwork jalankan `make icons` (ImageMagick + librsvg) supaya `assets/icons/ccode-<size>.png` ikut berubah, lalu `make build && make test`. `make build` menolak bila anchor mark tidak lagi unik atau masih ada path mark upstream — jangan melemahkan assertion itu. `make apply` mempromosikan ikon packaged, menjalankan plan payload plugin, dan mengganti nama identitas AppDir (`app/ccode`); `make install` hanya diperlukan bila integrasi user (launcher, ikon tema, unit systemd) perlu diperbarui; `make migrate` memindahkan instalasi pra-rebrand ke ejaan baru saat aplikasi tertutup (lihat ARCHITECTURE.md).

## UI atau IPC

Edit `src/renderer/linux-computer-use.js`, `src/renderer/activity-panel.js`, `src/main/activity.cjs`, atau modul UI/IPC terkait. Gunakan `make build && make test`. Hasil masih staged. Tutup CCode sebelum `make apply`, lalu buka melalui `make run`/launcher. `make install` hanya diperlukan bila path integrasi berubah.

Untuk preview terisolasi, jalankan `app/ccode` dengan `CCODE_DESKTOP_APPLICATION_NAME`, `CCODE_DESKTOP_USER_DATA_DIR`, dan `CCODE_DATA_BASE_DIR` menunjuk profil di `runtime/preview`. Sejak patch standalone, cara paling sederhana adalah menetapkan `CCODE_STANDALONE_ROOT` ke direktori uji lalu memakai `scripts/run.sh`; bootstrap env akan mengisi seluruh namespace (data, profil, database task/sesi, config MCP) dari root tersebut.

Ini bukan sandbox penuh: sebagian jalur masih menyentuh path di luar namespace (misalnya ikon/deep-link AppImage dan pembacaan config oleh proses yang belum direstart). Uji dengan root terpisah, jangan mengubah live MCP, dan jangan mengirim prompt saat hanya menguji UI. Port debugging lokal hanya digunakan untuk inspeksi pengembangan; jangan memasukkannya dalam launcher harian.

Jangan mengekspor env namespace di shell harian. Beberapa skrip menolak berjalan ketika menemukan variabel `CCODE_STANDALONE_ROOT` pada proses lain; shell persisten yang menyimpan variabel itu akan dianggap sebagai aplikasi yang masih aktif. Bersihkan env sebelum menjalankan `make install`, `data_backup.py`, atau verifikasi lain.

Pemeriksaan smoke minimal setelah `make build && make test`:

1. Jalankan `scripts/run.sh` dengan `CCODE_STANDALONE_ROOT` uji; pastikan workspace terbuka tanpa layar login.
2. Pastikan tidak ada `Unknown channel`, `No handler registered`, `ReferenceError`, atau `TypeError` pada log.
3. Kirim satu prompt pendek ke provider personal yang sudah dikonfigurasi, lalu restart dan pastikan task masih ada.
4. Jalankan `python3 scripts/data_backup.py backup|verify|restore` pada root uji.
5. Untuk perubahan katalog/discovery: tambahkan provider 9Router di root uji, pastikan form model list mulai **kosong**, lalu tekan tombol **Auto Detect** (jalur pengguna) atau `make models STANDALONE_ROOT=<root uji>` untuk mengisi provider terkelompok.

Setelah mengubah README, AGENTS, atau `docs/`, jalankan `make obsidian`: bila folder project ini dipakai sebagai vault (`.obsidian/` ada) perintah itu hanya menyegarkan `Index.md`, sedangkan untuk vault terpisah perintah itu menyalin dokumen plus frontmatter tag. `make obsidian-check` memeriksa selisih tanpa menulis.

## Memori dan CPU

Ukur dengan root terisolasi, bukan aplikasi pengguna: jalankan `CCODE_STANDALONE_ROOT=/tmp/zroot scripts/run.sh --remote-debugging-port=9224`, tunggu target halaman lewat `curl -sf http://127.0.0.1:9224/json/list`, lalu jumlahkan `Pss` dari `/proc/<pid>/smaps_rollup` untuk setiap proses yang environ-nya memuat root itu. RSS biasa menghitung halaman bersama berkali-kali, jadi PSS yang dipakai sebagai angka.

Catatan saat mengukur: proses anak Electron menulis ulang argv menjadi `/proc/self/exe`, sehingga pencocokan `cmdline` saja akan melewatkan renderer; cocokkan lewat environ atau pohon proses. Bersihkan root uji dengan mematikan proses yang environ-nya memuat root tersebut.

Knob yang tersedia: `CCODE_CUA_WARMUP=1` (kembalikan prefetch model OCR di MCP desktop), `MCP_SCREEN_AMBIENT=0` dan `MCP_SCREEN_NO_NUDGE=1` (matikan sinyal ambient dan sentakan pointer). Jangan menambahkan flag Chromium ke `scripts/run.sh` untuk mengejar memori: `--enable-low-end-device-mode` memang menghemat ~128 MB tetapi menyentuh perilaku render/hover, dan default harness ini sengaja tetap upstream. Jangan pula menaikkan batas heap V8 (`--js-flags=--max-old-space-size`) tanpa bukti: tambahannya hanya ~2 MB dan menahan pertumbuhan heap berisiko OOM pada task panjang.


## Backend

- Desktop: edit `services/desktop/ccode_fast_profile.py`; itu batas edit project untuk backend desktop dan file vendor (`server.py`, `capture.py`, `input.py`, `grounding.py`) tidak diubah dari sini. Uji profil dengan `python3 -m unittest tests.test_desktop_profile -v` (memakai server/input/capture palsu, tanpa portal). Verifikasi bahwa profil benar-benar terpasang pada namespace server asli: `cd services/desktop && MCP_SCREEN_PROFILE=ccode-fast .venv/bin/python -c "import sys;sys.path.insert(0,'.');import server,input;print(getattr(input.guard_user,'policy',None),getattr(server._maybe_shot,'policy',None),len(server.TOOLS))"`. Smoke permukaan tool tanpa portal: kirim `initialize` + `tools/list` (atau `tools/call screen_sense`) ke `services/desktop/bin/screen-mcp` lewat stdio. Knob perilaku (`CCODE_CUA_*`, `MCP_SCREEN_WAIT_MODE`, `MCP_SCREEN_AMBIENT`, `MCP_SCREEN_NO_NUDGE`) didokumentasikan di [COMPUTER_USE_IMPROVEMENTS.md](COMPUTER_USE_IMPROVEMENTS.md); jangan mengaktifkan portal atau menyentuh pointer pengguna hanya untuk menguji perubahan.
- Provider katalog: edit `src/local_only/catalog.py` (transform dijalankan atas file katalog terpasang, jadi hasilnya idempotent walau `app/resources` sudah pernah dipatch). Jangan menambah provider akun; tambah template baru di sana dan uji dengan `python3 -m unittest tests.test_catalog -v`.
- Activity: edit `src/main/activity.cjs` (query lokal) atau `src/renderer/activity-panel.js` (tampilan). - Token savers: edit `src/renderer/token-savers-panel.js`, `src/main/token-savers.cjs`, `src/main/token-savers-runtime.cjs`, atau `src/local_only/token_savers.py`. Smoke Settings → Token savers di root terisolasi: simpan setiap switch/mode, restart, pastikan nilainya bertahan, dan periksa tooltip/chart RTK. Jangan kirim prompt ke provider hanya untuk menguji panel.
- Default skills: taruh skill di `src/skills/<nama>/SKILL.md` (frontmatter hanya `name`, `description`, `when_to_use`, `license`, `metadata`; kunci Claude-Code lain masuk ke `metadata`), lalu `make build && make test`. Skill dikirim sebagai pack native `glm/packages/bundled-skills`, bukan plugin. Pertahankan seed `dynamic-workflows` vendor; marker `.ccode-skills.json` membatasi prune pada skill milik CCode. Uji integritas payload dan listing: `python3 -m unittest tests.test_skills -v`; uji promosi/rollback: `python3 -m unittest tests.test_apply_build -v`. ## Kandidat boot Windows hibrida (M1)

Jalankan `make build && make test`, lalu `python3 scripts/pack_windows.py`. Skrip memakai resource staged yang diverifikasi lewat manifest, mengunduh installer vendor 3.14.3 dengan SHA256 terpinsel, dan merakit ZIP kandidat M1 di `runtime/release-windows/`. Prasyarat build: Python 3, `7z`/`7zz`, ImageMagick `magick`, serta jaringan untuk installer dan paket native Codegraph Windows yang integrity-nya dipin. `--installer <path>` memakai unduhan lokal dengan pemeriksaan hash yang sama; `--staged <dir>` memilih build terverifikasi. Output tidak mengubah AppDir terpasang atau artifact Linux.

Lapisan JS tetap hasil patch 3.14.5; payload native unpacked berasal dari ASAR Windows dan menggantikan native Linux, termasuk helper ConPTY. Packager memperbarui hash header ASAR dalam resource executable, mempertahankan fuse Electron, dan membuang referensi sertifikat vendor yang tidak lagi berlaku setelah executable diubah. Kandidat tetap unsigned.

Output menyertakan `SHA256SUMS`, `candidate-manifest.json`, dan `M1-INSTRUCTIONS.txt`. ZIP berisi launcher PowerShell dengan root terisolasi, metadata OS/hash/root, serta log stdout/stderr. Pengguna menguji startup dan terminal di Windows sesuai instruksi itu; build Linux, unit test, dan checksum bukan bukti Windows berjalan. Ini belum NSIS, belum paritas fitur, dan bukan penyelesaian port source fork. M2–M5 menunggu gate M1 di [windowsrelease.md](../windowsrelease.md).

## Update the upstream baseline

Simpan baseline baru di baselines, baca package identity/hash, lalu perbarui project.json setelah meninjau versi. Cari kembali asset renderer dan simbol komponen. Build sengaja gagal saat anchor berubah; jangan menghapus assertion agar build terlihat berhasil. Verifikasi Computer Use, reasoning, profil pengguna, dan rollback sebelum mengganti launcher.

# Pengembangan lewat ohmypi

Jalankan `omp` dari root project. Mulai dengan meminta pembacaan AGENTS.md, lalu jelaskan perubahan dan hasil yang diinginkan.

Setiap pekerjaan memakai TODO yang diperbarui sepanjang proses; subagent hanya untuk bagian yang benar-benar memerlukannya. Setiap perubahan file project diikuti `make build`, pemeriksaan relevan, dan pembaruan Markdown terkait plus `make obsidian`. Setelah hasil terverifikasi, agent otomatis commit file pekerjaan dan push branch aktif ke remote terkonfigurasi, tanpa force-push atau menyertakan perubahan pengguna yang tidak terkait. Deployment tetap memakai `make apply` saat CCode sudah ditutup normal; autopush tidak berarti memaksa app/task berhenti atau menjalankan `make install`.

## Branding dan ikon

Mark CCode berasal dari `ccode-logo.svg`. Dua modul terpisah: `src/local_only/rebrand.py` berjalan paling awal di `scripts/build.py` dan menulis ulang seluruh token produk upstream (env, IPC, skema URL, layout, id plugin, judul proses, identifier) dalam satu pass — `assert_clean()` menggagalkan build bila ada sisa, dan ejaan lama hidup di `rebrand.PREVIOUS_*` untuk kode migrasi; `src/local_only/branding.py` berjalan paling akhir di build dan hanya mengganti mark. Setelah mengubah artwork jalankan `make icons` (ImageMagick + librsvg) supaya `assets/icons/ccode-<size>.png` ikut berubah, lalu `make build && make test`. `make build` menolak bila anchor mark tidak lagi unik atau masih ada path mark upstream — jangan melemahkan assertion itu. `make apply` mempromosikan ikon packaged, menjalankan plan payload plugin, dan mengganti nama identitas AppDir (`app/ccode`); `make install` hanya diperlukan bila integrasi user (launcher, ikon tema, unit systemd) perlu diperbarui; `make migrate` memindahkan instalasi pra-rebrand ke ejaan baru saat aplikasi tertutup (lihat ARCHITECTURE.md).

## UI atau IPC

Edit `src/renderer/voice-input.js`, `src/renderer/linux-computer-use.js`, `src/renderer/activity-panel.js`, `src/main/voice.cjs`, atau `src/main/activity.cjs`. Gunakan `make build && make test`. Hasil masih staged. Tutup CCode sebelum `make apply`, lalu buka melalui `make run`/launcher. `make install` hanya diperlukan bila path integrasi berubah.

Untuk preview terisolasi, jalankan `app/ccode` dengan `CCODE_DESKTOP_APPLICATION_NAME`, `CCODE_DESKTOP_USER_DATA_DIR`, dan `CCODE_DATA_BASE_DIR` menunjuk profil di `runtime/preview`. Sejak patch standalone, cara paling sederhana adalah menetapkan `CCODE_STANDALONE_ROOT` ke direktori uji lalu memakai `scripts/run.sh`; bootstrap env akan mengisi seluruh namespace (data, profil, database task/sesi, config MCP) dari root tersebut.

Ini bukan sandbox penuh: sebagian jalur masih menyentuh path di luar namespace (misalnya ikon/deep-link AppImage dan pembacaan config oleh proses yang belum direstart). Uji dengan root terpisah, jangan mengubah live MCP, dan jangan mengirim prompt saat hanya menguji UI. Port debugging lokal hanya digunakan untuk inspeksi pengembangan; jangan memasukkannya dalam launcher harian.

Jangan mengekspor env namespace di shell harian. Beberapa skrip menolak berjalan ketika menemukan variabel `CCODE_STANDALONE_ROOT` pada proses lain; shell persisten yang menyimpan variabel itu akan dianggap sebagai aplikasi yang masih aktif. Bersihkan env sebelum menjalankan `make install`, `data_backup.py`, atau verifikasi lain.

Pemeriksaan smoke minimal setelah `make build && make test`:

1. Jalankan `scripts/run.sh` dengan `CCODE_STANDALONE_ROOT` uji; pastikan workspace terbuka tanpa layar login.
2. Pastikan tidak ada `Unknown channel`, `No handler registered`, `ReferenceError`, atau `TypeError` pada log.
3. Kirim satu prompt pendek ke provider personal yang sudah dikonfigurasi, lalu restart dan pastikan task masih ada.
4. Jalankan `python3 scripts/data_backup.py backup|verify|restore` pada root uji.
5. Untuk perubahan katalog/discovery: tambahkan provider 9Router di root uji, pastikan form model list mulai **kosong**, lalu tekan tombol **Auto Detect** (jalur pengguna) atau `make models STANDALONE_ROOT=<root uji>` untuk mengisi provider terkelompok.

Setelah mengubah README, AGENTS, atau `docs/`, jalankan `make obsidian`: bila folder project ini dipakai sebagai vault (`.obsidian/` ada) perintah itu hanya menyegarkan `Index.md`, sedangkan untuk vault terpisah perintah itu menyalin dokumen plus frontmatter tag. `make obsidian-check` memeriksa selisih tanpa menulis.

## Memori dan CPU

Ukur dengan root terisolasi, bukan aplikasi pengguna: jalankan `CCODE_STANDALONE_ROOT=/tmp/zroot scripts/run.sh --remote-debugging-port=9224`, tunggu target halaman lewat `curl -sf http://127.0.0.1:9224/json/list`, lalu jumlahkan `Pss` dari `/proc/<pid>/smaps_rollup` untuk setiap proses yang environ-nya memuat root itu. RSS biasa menghitung halaman bersama berkali-kali, jadi PSS yang dipakai sebagai angka.

Catatan saat mengukur: proses anak Electron menulis ulang argv menjadi `/proc/self/exe`, sehingga pencocokan `cmdline` saja akan melewatkan renderer; cocokkan lewat environ atau pohon proses. Bersihkan root uji dengan mematikan proses yang environ-nya memuat root tersebut.

Knob yang tersedia: `CCODE_CUA_WARMUP=1` (kembalikan prefetch model OCR di MCP desktop), `MCP_SCREEN_AMBIENT=0` dan `MCP_SCREEN_NO_NUDGE=1` (matikan sinyal ambient dan sentakan pointer). Jangan menambahkan flag Chromium ke `scripts/run.sh` untuk mengejar memori: `--enable-low-end-device-mode` memang menghemat ~128 MB tetapi menyentuh perilaku render/hover, dan default harness ini sengaja tetap upstream. Jangan pula menaikkan batas heap V8 (`--js-flags=--max-old-space-size`) tanpa bukti: tambahannya hanya ~2 MB dan menahan pertumbuhan heap berisiko OOM pada task panjang.


## Backend

- Desktop: edit `services/desktop/ccode_fast_profile.py`; itu batas edit project untuk backend desktop dan file vendor (`server.py`, `capture.py`, `input.py`, `grounding.py`) tidak diubah dari sini. Profil dimuat server saat MCP_SCREEN_PROFILE=ccode-fast, jadi aturan lupa-build tidak berlaku: perubahannya aktif begitu MCP desktop dimuat ulang (chat baru atau aplikasi dibuka ulang). Uji profil dengan `python3 -m unittest tests.test_desktop_profile -v` (memakai server/input/capture palsu, tanpa portal). Verifikasi bahwa profil benar-benar terpasang pada namespace server asli: `cd services/desktop && MCP_SCREEN_PROFILE=ccode-fast .venv/bin/python -c "import sys;sys.path.insert(0,'.');import server,input;print(getattr(input.guard_user,'policy',None),getattr(server._maybe_shot,'policy',None),len(server.TOOLS))"`. Smoke permukaan tool tanpa portal: kirim `initialize` + `tools/list` (atau `tools/call screen_sense`) ke `services/desktop/bin/screen-mcp` lewat stdio. Knob perilaku (`CCODE_CUA_*`, `MCP_SCREEN_WAIT_MODE`, `MCP_SCREEN_AMBIENT`, `MCP_SCREEN_NO_NUDGE`) didokumentasikan di [COMPUTER_USE_IMPROVEMENTS.md](COMPUTER_USE_IMPROVEMENTS.md); jangan mengaktifkan portal atau menyentuh pointer pengguna hanya untuk menguji perubahan.
- Voice: edit `services/voice/worker.py` / `terminology.py`. Restart CCode untuk melepas worker yang masih menyimpan kode/model lama.
- Provider katalog: edit `src/local_only/catalog.py` (transform dijalankan atas file katalog terpasang, jadi hasilnya idempotent walau `app/resources` sudah pernah dipatch). Jangan menambah provider akun; tambah template baru di sana dan uji dengan `python3 -m unittest tests.test_catalog -v`.
- Activity: edit `src/main/activity.cjs` (query lokal) atau `src/renderer/activity-panel.js` (tampilan). Uji agregasi dengan `python3 -m unittest tests.test_activity -v`: test membuat fixture SQLite sendiri dan menjalankannya lewat node/Electron, jadi tidak perlu membuka aplikasi. CSS renderer statis dari upstream — kelas Tailwind yang tidak dipakai upstream (mis. `grid-cols-5`, `h-[11px]`, `bg-primary/25`) tidak punya aturan, jadi tulis UI dengan kelas yang ada di `out/renderer/assets/styles-*.css` atau gaya inline, dan periksa hasilnya di aplikasi (bukan dari asumsi kelas).
- Token savers: edit `src/renderer/token-savers-panel.js`, `src/main/token-savers.cjs`, `src/main/token-savers-runtime.cjs`, atau `src/local_only/token_savers.py`. Jalankan `python3 -m unittest tests.test_token_savers -v` dan `make build && make test`; tes RTK memakai executable palsu untuk rewrite pada status 0/3, no-match pada status 1, status gagal, dan approval normal. Smoke Settings → Token savers di root terisolasi: simpan setiap switch/mode, restart, pastikan nilainya bertahan, dan periksa tooltip/chart RTK. Jangan kirim prompt ke provider hanya untuk menguji panel.
- Default skills: taruh skill di `src/skills/<nama>/SKILL.md` (frontmatter hanya `name`, `description`, `when_to_use`, `license`, `metadata`; kunci Claude-Code lain masuk ke `metadata`), lalu `make build && make test`. Skill dikirim sebagai pack native `glm/packages/bundled-skills`, bukan plugin. Pertahankan seed `dynamic-workflows` vendor; marker `.ccode-skills.json` membatasi prune pada skill milik CCode. Uji integritas payload dan listing: `python3 -m unittest tests.test_skills -v`; uji promosi/rollback: `python3 -m unittest tests.test_apply_build -v`. Cek agent pada root uji: `CCODE_STANDALONE_ROOT=<dir uji> ELECTRON_RUN_AS_NODE=1 app/ccode app/resources/glm/ccode.cjs skills list`; 32 nama harus muncul sekali sebagai `system/bundled`, tanpa `ccode-skills:`. Periksa Settings → Skills: skill bawaan berlabel Default, dan Plugins tidak menampilkan CCode Skills. Jangan gunakan namespace asli untuk smoke.
- Built-in subagents: edit `src/local_only/subagents.py`, bukan bundle terkemas. Katalog ini memasang data ke host, kontrol Settings, dan runtime agent. Jalankan `python3 -m unittest tests.test_subagents -v`, lalu `make build && make test`. Smoke pada root terisolasi: pastikan 12 nama muncul, toggle tiap role tersimpan setelah restart, model mewarisi model sesi, dan role nonaktif hilang dari prompt serta tidak dapat di-dispatch. Agent plugin `visual-judge` tetap terpisah.
- Katalog MCP: edit `services/mcp/` untuk package/version, `src/main/mcp-catalog.cjs` untuk bootstrap/install/probe, `src/renderer/mcp-catalog.js` untuk baris katalog, atau `src/local_only/mcp_catalog.py` untuk pemasangan baris itu ke daftar native `FTn`. Dependency default harus terpasang saat build dan dipromosikan bersama resource `mcp/`, bukan diunduh pada pemakaian pertama. Periksa hasil di aplikasi: baris opsional tampil di daftar Installed dengan tombol Install, lalu berubah menjadi baris native ber-switch setelah install. Verifikasi tool nyata (bukan handshake) memakai `node services/mcp/test.cjs` untuk batas runtime dan `ELECTRON_RUN_AS_NODE=1 app/ccode runtime/build/resources/mcp/smoke.cjs runtime/build/resources --all` untuk operasi tool pada root sementara; credentials probe tetap privat dan tidak boleh masuk fixture tracked.
- Plugin n8n: source di `src/plugins/n8n/`, registry pinned di `src/local_only/n8n_plugin.py`, dependency di `services/mcp/package.json`/lockfile. Native cache menyalin manifest, entrypoint `dist/mcp/server.js`, dan seluruh skill; jangan bergantung pada ancestry cache untuk menemukan dependency. Entrypoint mengambil runtime MCP dari AppDir milik binary Electron. Uji batas launcher dengan `node services/mcp/test-n8n.cjs`; regresi native enable/disable dengan `python3 -m unittest discover -s tests -p test_n8n_plugin.py -v`. Smoke UI harus menyimpan URL/key melalui form native, membuktikan koneksi serta operasi workflow nyata pada instance uji, dan memeriksa seluruh skill hilang saat disable. Jangan memakai credentials atau workflow live untuk uji.
- Plugin Marketplace: kompatibilitas publisher ada di `src/main/marketplace-compat.cjs` (template) dan `src/local_only/marketplace.py` (enam ejaan kontrak dari `rebrand.previous()` + sembilan anchor agent). Jangan menulis ejaan upstream di runtime atau test secara literal: pakai `rebrand.previous(...)`/`marketplace.PLACEHOLDERS`, karena `render_runtime()` dan `rebrand.assert_clean()` menggagalkan build bila ada token di luar kontrak. Uji dengan `python3 -m unittest tests.test_marketplace -v` (kontrak runtime lewat node, lokalisasi idempoten, keunikan anchor) lalu `make build && make test`. Verifikasi perilaku nyata tanpa membuka UI: jalankan `ELECTRON_RUN_AS_NODE=1 app/ccode <agent> app-server --stdio` pada root terisolasi, lalu panggil `plugins/marketplace/update`, `plugins/describe`, dan `plugins/install` (`workspace:{workspacePath,workspaceKey}`); refresh sukses bila `diagnostics` kosong dan `pluginCount` ikut naik, install sukses bila `installedPlugins` terisi, dan respons tidak boleh memuat teks Cina. Manifest marketplace lokal untuk uji cukup satu file JSON dengan `source:{source:"url",type:"zip",url,sha256}` di dalam root uji (jangan di `/tmp` polos: penambahan source menyalin direktorinya).
- Model sync: edit `services/model-sync/sync.py`. Langkah discovery 9Router membaca `GET /v1/models` gateway lokal, mengelompokkan per namespace (combo terpisah, ambang 10 model, sisanya `· lainnya`), dan menulis provider + manual rule ke `provider_config.json`; pemicunya unit path standalone pada file itu, kondisi provider kosong/belum dikelompokkan, dan timer 60 detik dengan TTL 12 jam. Uji dengan `python3 -m unittest tests.test_model_sync -v` (fixture gateway, tanpa jaringan); paksa refresh dengan `make models` (atau `systemctl --user start ccode-model-sync.service` untuk namespace standalone; unit `rebrand.PREVIOUS_UNIT`/`rebrand.PREVIOUS_VANSROUTER_UNIT` bila memang ingin menyentuh konfigurasi instalasi pra-rebrand). Jangan menulis `provider_config.json` dari proses lain tanpa melewati lock + backup sync: `commit()` menolak write yang mengurangi inventori model, dan `optionSpecs.reasoningLevel` wajib ada di setiap manual rule.

Venv dan model sudah dipindahkan. Untuk mesin baru, buat kembali venv, pasang dependency yang tercatat, sediakan PyGObject/GStreamer/PipeWire/portal/wl-clipboard untuk desktop dan FFmpeg/pw-record untuk voice. Jangan menyalin venv antarversi Python lalu menganggapnya portabel.

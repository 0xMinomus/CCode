# Linux release UI audit

Mode: after, from the saved global preference. Scope: removal of the Voice composer controls and the downloadable n8n plugin's native Marketplace/settings surfaces. This is not a redesign or a whole-application accessibility certification.

Design read: an Operate surface for CCode users, preserving the incumbent application family. ENERGY 1 / RHYTHM 1 / MOTION 1. Existing typography, spacing, surface colors, buttons, cards, disclosures, fields, and switches remain authoritative. No new visual assets, CSS, fonts, icon family, navigation structure, or animations were introduced.

## Findings

No new visual-family defects found in this scope. No UI rewrite is proposed.

## Delivery gate

- Hard Gate PASS for the release delta: the running composer has zero Voice controls and retains all 12 commands; no horizontal overflow at inspected 1200px and 1920px viewport widths; no new claims, assets, links, colors, or disabled placeholder features were added. Native Marketplace installation, configuration save, and enablement controls were exercised. Renderer error collections were empty. Keyboard Tab reached Add context with `:focus-visible` true.
- Purpose-Gate PASS: existing native components supply every visual treatment. Removing Voice reduces the toolbar without adding decoration; n8n uses the same Marketplace card/detail and plugin settings form as other plugins. No new gradient, glow, shadow, illustration, badge style, typography, or motion requires a separate visual language.
- Liveliness PASS: the existing composer remains the workspace focal point, existing whitespace separates task entry from navigation, and the CCode mark plus the app's established surfaces remain unchanged. The calm, uniform, hover-only dials describe preservation, not a new design claim.
- Craftsmanship and consistency PASS for changed behavior: public-asset installation showed the native Installing state and then the MCP/15-skill component list; native configuration saved; disabling the plugin removed its visible skill rows and returned an empty n8n runtime skill list. The shipped AppImage and installed RPM opened the workspace without login or renderer errors. No competing component family was introduced.

## Evidence and limits

- Inspected rendered composer, native Marketplace details, and native plugin configuration in an isolated namespace.
- Inspected the final AppImage's rendered composer. Its slash picker contained 12 commands, Voice button count was zero, and the page had no horizontal overflow.
- Installed the final RPM into a temporary root with scriptlets/dependency checks disabled, then launched its application under a separate namespace. The same composer checks passed.
- Installed n8n from the published GitHub zip through Marketplace, saved a non-secret smoke-only key in the native form, disabled n8n through its native switch, and exercised MCP `get_node` against the packaged database without a live n8n instance.
- Theme styles and contrast tokens were not changed. This audit does not claim a full contrast audit of inherited application text, a light-theme regression suite, mobile support, or verification on another distro.
- No model prompt was sent for UI inspection. Temporary profiles and smoke scripts are removed after verification.
